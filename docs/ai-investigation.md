# BrandShield AI — AI Investigation Layer

## Overview

The AI investigation layer provides analyst-style explanations of why a candidate was flagged.

**Key principle:** The deterministic detection engine is the source of truth for all numerical scores. The AI layer explains and summarizes — it never changes scores or invents evidence.

---

## Architecture

```
POST /api/v1/investigation/candidates/{id}/analyze
POST /api/v1/investigation/candidates/{id}/ask
          ↓
    Load context from DB
    (candidate + brand + evidence + risk assessment)
          ↓
    AIInvestigator.investigate() / .ask()
    ┌─────────────────────────────────────┐
    │ OpenAIInvestigator (if key is set)  │─── falls back on any failure ───┐
    │ or                                  │                                  │
    │ TemplateInvestigator (always works) │◄────────────────────────────────┘
    └─────────────────────────────────────┘
          ↓
    Enforce invariant:
      result.risk_score = ctx.risk_score  ← AI cannot change this
      result.risk_level = ctx.risk_level  ← AI cannot change this
          ↓
    Return InvestigationResult / AskResponse
```

---

## Endpoints

### `POST /api/v1/investigation/candidates/{candidate_id}/analyze`

Generates a structured investigation summary.

**Prerequisites:** Run `POST /api/v1/detection/candidates/{id}/analyze` first to generate a risk assessment.

**Response:**
```json
{
  "candidate_id": "...",
  "risk_score": 83,
  "risk_level": "CRITICAL",
  "summary": "This Twitter account was flagged...",
  "risk_explanation": "The risk score of 83/100 places this...",
  "key_findings": ["Identity Similarity: 90%...", "..."],
  "evidence_summary": ["Username Match: Handle matches brand exactly.", "..."],
  "recommended_actions": ["Preserve evidence...", "File takedown report..."],
  "confidence_note": "High confidence (85%)...",
  "generated_by": "ai",
  "generated_at": "2025-01-15T10:30:00Z"
}
```

### `POST /api/v1/investigation/candidates/{candidate_id}/ask`

Answer a natural-language analyst question.

**Request:**
```json
{ "question": "Why is this candidate considered high risk?" }
```

**Response:**
```json
{
  "candidate_id": "...",
  "question": "Why is this candidate considered high risk?",
  "answer": "This candidate scored 83/100 (CRITICAL) primarily because...",
  "generated_by": "template",
  "generated_at": "2025-01-15T10:30:01Z"
}
```

## Provider Configuration

Set in `backend/.env`:

| Variable | Purpose |
|---|---|
| `AI_PROVIDER` | Set to `openai` for live AI. Leave blank for template fallback. |
| `AI_API_KEY` | Your OpenAI API key. Never committed. |
| `AI_MODEL` | Model name (default: `gpt-4o-mini`) |
| `AI_MAX_TOKENS` | Response length limit (default: 800) |
| `AI_TIMEOUT_SECONDS` | LLM call timeout (default: 15s) |

## Template Fallback

The template fallback produces deterministic, grounded output using only:
- The stored risk level and score
- The top detection reasons
- The stored evidence records
- The signal breakdown

It is always available — no external API required. The dashboard never breaks because AI is unavailable.

`generated_by` is always either `"ai"` or `"template"` — never hidden.

---

## Grounding Rules (enforced in prompt and in code)

1. Use ONLY the supplied candidate data and evidence.
2. Do NOT invent URLs, domain names, or platform activity.
3. Do NOT change the numerical risk score.
4. Do NOT claim malicious intent without evidence.
5. Clearly distinguish OBSERVED EVIDENCE from ANALYST RECOMMENDATIONS.
6. Synthetic demo data is labelled as synthetic.

---

## Security

- API keys are loaded from environment variables only — never hardcoded.
- The risk_score and risk_level in the response are always overwritten with the values from the DB after the AI response — the LLM output for these fields is ignored.
- All AI output is parsed as structured JSON and validated against Pydantic schemas before being returned.
- The AI never receives raw SQL, database connection strings, or secret values.

---

## Demo Mode

The hackathon demo works fully without an LLM key. The template fallback produces:
- A concise analyst summary
- Key signal findings
- Evidence-backed points
- Recommended analyst actions
- A confidence note

The UI labels the output as `Generated by: Evidence-based fallback` vs `Generated by: AI`.
