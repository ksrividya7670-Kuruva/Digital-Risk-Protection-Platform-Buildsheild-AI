# AI Investigation and Explainability

## Role of the AI

The investigator is an analyst assistant. Detection, risk thresholds, score,
risk level, and confidence are produced by the deterministic detection engine.
AI text does not create or update assessments. The analyze response always gets
its score, risk level, findings, evidence summary, and confidence note from
stored backend data; only its short narrative summary comes from the configured
provider.

The natural-language ask endpoint uses the same read-only context and has a
deterministic answer when the provider is not available.

## Grounding and response validation

The service sends a structured JSON representation of candidate identity,
platform, data source, metadata, brand, risk assessment, signals, reasons, and
stored evidence. Candidate and evidence text are treated as untrusted input,
not as instructions. The model is told to use only this context, distinguish
observations from recommendations, treat demo data as synthetic, and not infer
malicious intent.

The provider response is validated against a strict Pydantic schema that
accepts only a bounded summary string. Any additional or malformed fields
trigger the template fallback. Evidence summaries, key findings,
recommendations, deterministic confidence, risk score, and risk level are
assembled by the backend from the stored context. A model-generated URL absent
from the supplied context is rejected and the fallback is used.

## Deterministic fallback

Live AI is optional. The service returns `generated_by: "template"` when no
provider/key is configured, or when a provider call times out, fails, returns
malformed output, or fails validation. The fallback uses the stored risk tier,
score, confidence, signal breakdown, detection reasons, and evidence. The API
remains available and makes no claim that fallback text was generated by an
LLM.

## Configuration

Set the following environment variables in the backend environment:

```dotenv
AI_PROVIDER=openai
AI_API_KEY=your-provider-key
AI_MODEL=gpt-4o-mini
AI_MAX_TOKENS=800
AI_TIMEOUT_SECONDS=15
```

Leave `AI_PROVIDER` and `AI_API_KEY` empty for deterministic demo mode. Never
put a real key in source control, frontend code, API responses, logs, or test
fixtures. Tests mock provider responses and do not make external LLM calls.

The provider interface is isolated behind `AIInvestigator`; the current live
adapter supports OpenAI-compatible chat completions. Unknown/unconfigured
providers use template output rather than returning success-shaped AI output.

## Security and limitations

- No provider output is allowed to modify numerical scores, thresholds, stored
  evidence, or candidate records.
- Observed evidence is rendered from database records; provider-generated
  prose cannot add items to the evidence list.
- Secrets are loaded from environment configuration and are never part of the
  request context.
- Demo records retain their synthetic marker and are identified as synthetic
  in the evidence summary.
- Provider prose is still generated text. Schema validation and URL checks
  reduce unsupported output but cannot prove every natural-language statement
  true. Analysts must verify evidence and recommendations before acting.
- An AI investigation is not a platform confirmation or a final determination
  of malicious intent. Human review is required.
- Investigation results are not separately persisted in this MVP; each request
  reads the latest deterministic assessment and its current evidence.
